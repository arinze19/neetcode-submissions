=============== NOTES ===============
1. A very deep tree is a reason to prefer BFS
2. Prefer BFS in cases where stopping early can reduce work (shortest path) 
3. Prefer DFS when Tree is extremely wide
4. BST is a top-down property
5. For BFS, discovering a node != processing it 
6. BFS can be used for 
    -> serialization 
    -> shortest path on an unweighted graph

=============== PATTERNS ===============
1. BFS template 
    -> setup per level accumulator 
    -> per node work 
    -> commit level result
2. BST 
    -> iterative O(1) and recursive O(h)
    -> self balancing BST are mainly used in production systems
    -> BST hardly has duplicate values but if there are duplicates, prefer to keep duplicate on right side
    -> never bulk build a BST from sorted data
        * shuffle first; insert from median 
        * build from middle outward 
    -> iterative version for kth smallest element since we can break out at a certain point in time 
    -> LCA on BST
        Walk down from the root. 
        While both targets are on the same side, keep going. 
        The first node where they disagree, or where one target is the node itself, is the answer
    -> validating BST
    -> optimising for repeated kth-smallest queries
        * each node store the number of each subtree including itself [order statistic tree]
